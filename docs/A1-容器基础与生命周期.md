# A1 容器基础与生命周期：学习笔记

> 阶段计划 Phase 0「容器夯实期」第一项。目标是搞清镜像/容器关系、分层与写时复制、容器生命周期，以及 `docker run` 常用参数的真实含义。
> 实验环境：Ubuntu VM，普通用户 `lyh`（已加入 `docker` 组，免 sudo），镜像源 `docker.m.daocloud.io`。

## 一、疑惑点记录（Q&A）

### 1. `docker build -t my-mini:v1 .` —— my-mini:v1 是容器名吗？`.` 是 Dockerfile 路径吗？
- **不是容器名，是镜像名（tag）。** `-t` = tag，`my-mini` 是镜像名，`v1` 是标签。容器是镜像 `run` 之后才生成的实例。
- **`.` 是构建上下文路径**（不是 Dockerfile 路径本身）。Docker 把当前目录打包发给守护进程，默认在该目录找名为 `Dockerfile` 的文件。Dockerfile 不在当前目录或名字不同，用 `-f 路径/Dockerfile` 指定。

### 2. 构建报错 can't create /app/message.txt: nonexistent directory
- 原因：`alpine` 基础镜像根目录下**没有 `/app` 目录**，shell 的 `>` 重定向写文件要求父目录已存在。换个镜像（ubuntu/busybox）默认同样没有 `/app`，都得先 `mkdir -p /app`。修复：在 `RUN` 里先建目录。

### 3. `--rm` 不就是"删除"吗？docker run 不是要"运行"吗？
- `--rm` 是 `docker run` 的参数，全称 `--remove`，意思是**容器退出后自动删除**。和 bash 的 `rm` 删除命令无关，只是缩写相同。不加 `--rm`，容器跑完留下 `Exited` 状态的记录，得手动 `docker rm` 清理；镜像不会被删。

### 4. `docker run --rm my-mini:v1` 是不是命令执行完就退出？相当于一次性容器？
- 对。容器生命周期绑定它的**主进程**：`my-mini` 的 `CMD` 是 `cat /app/message.txt`，命令一执行完，主进程结束，容器退出，`--rm` 顺手删掉。就是一次性容器，适合跑完即弃的验证/脚本。对比：`nginx` 这类服务容器主进程常驻前台，不主动停就不退出。

### 5. 写时复制（CoW）验证时，第二个容器没有回显，是不是"原镜像本身没有任何东西"？
- 不准确。准确说法是：**原镜像里没有 `/tmp/x` 这个文件**。alpine 镜像本身有完整文件系统（`/bin/sh`、`/etc` 等都在），只是第一个容器临时写的 `/tmp/x` 只活在它自己的可写层，退出后随容器消失，新容器从镜像全新启动自然看不到。这正是 CoW：容器层改动不污染镜像、不影响其他容器。

### 6. 本地没有 `alpine:latest` 时，`docker run alpine ...` 会自动拉取吗？
- 会。本地找不到指定镜像时，Docker 默认从配置的镜像仓库（默认 docker hub）自动 pull 对应标签，再启动。所以没镜像也能直接跑（这也是为什么之前"额外多下了一个 alpine:latest"）。
- 想禁止自动拉取（离线或先确认）：加 `--pull=never`，本地没有就直接报错。

### 7. 运行了容器，`docker ps` 却没内容，也没加 `--rm`，为什么？
- `docker ps` 默认只显示**正在运行**的容器。你的命令主进程是 `sh -c '...'`，执行完 shell 退出，容器状态变 `Exited`。没加 `--rm` 只是在 `docker ps -a`（看所有容器，含已停止）里留着，不在 `docker ps` 默认列表里。
- 区分：`docker ps` = 运行中；`docker ps -a` = 全部（含 Exited）；`--rm` = 退出后自动删记录。

### 8. `sh -c'echo ...'` 连写报错 `sh: illegal option -h`
- `-c` 和命令字符串之间**少了空格**，被连成整体 `-c'echo liuyuhang-test...'` 当作选项串逐字符解析，遇到 `liuyuhang` 里的 `h` 字符判定为非法选项。正确写法：`-c 'echo ...'` 留空格、命令串用引号。

### 9. 怎样"既执行命令又让容器保持运行"（能在 docker ps 看到）？
- 主进程得常驻。用 `tail -f /dev/null`（或 `sleep infinity`）当"兜底主进程"不退出：
  ```bash
  docker run -d --name box2 alpine sh -c 'echo started > /tmp/log; tail -f /dev/null'
  ```
  命令先执行，再进入常驻，容器一直 `Up`，还能 `docker exec` 进去复查。

## 二、参数原本的释义

| 参数 / 命令 | 原本含义 | 说明 |
|---|---|---|
| `docker build -t <name:tag> <ctx>` | 构建镜像 | `-t` 打标签；`<ctx>` 是构建上下文目录（默认含 Dockerfile） |
| `docker run [opts] <镜像> [命令]` | 从镜像启动容器 | 不写 `[命令]` 用镜像默认 CMD；写了就替换 CMD |
| `--rm` | 容器退出后自动删除 | 只删容器记录，不删镜像 |
| `-i` / `--interactive` | 保持 STDIN 打开 | 容器能接收输入 |
| `-t` / `--tty` | 分配伪终端 | 输出带终端格式，支持交互 |
| `-it` | 两者合写 | 进交互式 shell 时用（`-it alpine sh`） |
| `-d` / `--detach` | 后台运行 | 立即回到终端，容器在后台 `Up` |
| `--name <n>` | 给容器命名 | 方便 `docker exec`/`rm` 引用，避免随机名 |
| `sh -c 'cmd'` | shell 执行命令串 | `-c` = command，把后面字符串当脚本执行；替代镜像默认 CMD，是常见容器主进程写法 |
| `docker exec -it <n> sh` | 进入运行中容器 | 容器必须处于 `Up` 状态；不进入新容器，是在已有容器内执行 |
| `docker ps` / `docker ps -a` | 列出容器 | 前者只显示运行中，后者含已停止 |
| `docker images` | 列出本地镜像 | `DISK USAGE` 实际磁盘占用，`CONTENT SIZE` 逻辑内容大小（共享层时前者 < 后者） |
| `docker rm -f <n/id>` | 删除容器 | `-f` 强制删运行中容器 |

**两个易混概念**
- 镜像（image）是静态模板，存在磁盘；容器（container）是镜像运行起来的实例，有生命周期。
- `docker run` 一个镜像 = 新建一个容器实例；`docker exec` 是进一个已存在的运行容器。

## 三、适用场景

| 场景 | 推荐写法 | 关键点 |
|---|---|---|
| 一次性验证 / 跑脚本 | `docker run --rm <img> <cmd>` | 跑完即清，不留 Exited 垃圾 |
| 交互式调试 | `docker run -it --name x <img> sh` | 进去手动敲命令；exit 后容器停 |
| 后台常驻服务 | `docker run -d --name x <img> <常驻进程>` | 主进程必须前台不退出（nginx / tail -f /dev/null） |
| 进运行中容器排查 | `docker exec -it x sh` | 容器须 `Up`；可在容器内读写文件 |
| 容器内向脚本传参 | `sh -c 'echo $1' sh arg1` | 第一个参数是 `$0`（脚本名），`arg1` 是 `$1` |
| 看所有容器状态 | `docker ps -a` | 排查"为什么 ps 看不到" |
| 清理停止的容器 | `docker rm $(docker ps -aq -f status=exited)` | 保持环境干净 |

**引号陷阱**：`sh -c` 的命令串用单引号最安全。双引号会让 `$变量` 被宿主机 shell 先展开，再传给容器内的 sh，常得到非预期结果。

## 四、A1 实验复盘（7 项）

| 实验 | 命令要点 | 验证结论 |
|---|---|---|
| 1 | `run --rm alpine sh -c '...'` | 一次性容器，无残留 |
| 2 | `run alpine sh -c '...'`（无 --rm） | `docker ps -a` 见 Exited 残留 |
| 3 | `run -it --name box1 alpine sh` | 交互式 shell，exit 后容器停 |
| 4 | `run -d --name box2 alpine sh -c '...; tail -f /dev/null'` | 后台常驻，`docker ps` 见 Up |
| 5 | `exec -it box2 sh` + `exec box2 sh -c 'cat ...'` | 进入运行中容器读写/复查文件 |
| 6 | `run --rm alpine sh -c 'echo hello $1' sh world` | 传参输出 `hello world` |
| 7 | `run --rm my-mini:v1` + `run -d --name mini-box my-mini:v1 tail -f /dev/null` | 自构建镜像一次执行 + 常驻 |
